# 云笔记前端开发任务

## 项目概述

本任务文档包含云笔记前端项目的开发任务：
- **note-web**：主要前端服务（端口 6000），基于 Electron 框架实现跨平台支持

## 三、开发规范

### 3.1 代码规范

- 遵循 ESLint 规则
- 使用 Prettier 格式化
- 组件命名使用 PascalCase
- 函数命名使用 camelCase
- 常量命名使用 UPPER_SNAKE_CASE
- 文件命名使用 kebab-case（小写字母+连字符）

### 3.2 组件化要求

#### 3.2.1 组件设计原则

- **单一职责原则**：每个组件只负责一个功能，避免组件功能过于复杂
- **高内聚低耦合**：组件内部逻辑紧密相关，组件之间依赖最小化
- **可复用性**：通用组件应设计为可复用，避免重复代码
- **可替换性**：组件应设计为可替换的，便于后续升级或替换实现

#### 3.2.2 组件分类

- **基础组件（Base Components）**：
  - 按钮、输入框、图标等基础 UI 组件
  - 存放路径：`src/components/base/`
  - 要求：高度可复用，不包含业务逻辑

- **业务组件（Business Components）**：
  - 笔记卡片、笔记本列表等业务相关组件
  - 存放路径：`src/components/business/`
  - 要求：包含业务逻辑，可复用于不同页面

- **布局组件（Layout Components）**：
  - 页面布局、导航栏等布局相关组件
  - 存放路径：`src/layouts/`
  - 要求：定义页面结构，组合其他组件

- **页面组件（Page Components）**：
  - 具体页面组件
  - 存放路径：`src/pages/`
  - 要求：组合业务组件和布局组件，实现页面功能

#### 3.2.3 组件接口设计

- **Props 接口**：
  - 使用 TypeScript 或 PropTypes 定义组件 Props 类型
  - Props 应该是可预测的，避免复杂的对象结构
  - 提供默认值和必填标识
  - 使用明确的命名，避免歧义

- **事件接口**：
  - 使用回调函数传递事件
  - 事件命名使用 `on` 前缀（如 `onClick`、`onChange`）
  - 事件参数应该清晰明确

- **插槽接口**：
  - 使用 children 或具名插槽支持内容自定义
  - 提供默认插槽内容

#### 3.2.4 组件通信方式

- **父子组件通信**：通过 Props 和回调函数
- **兄弟组件通信**：通过共同父组件或状态管理
- **跨层级通信**：通过 Context API 或 Redux
- **全局状态**：使用 Redux Toolkit 管理

#### 3.2.5 组件扩展性设计

- **配置化**：通过配置对象控制组件行为，而非硬编码
- **插槽扩展**：提供插槽支持自定义内容
- **Hook 扩展**：暴露自定义 Hook 供外部使用
- **事件扩展**：提供生命周期事件钩子（如 `onMount`、`onUpdate`）

#### 3.2.6 组件替换策略

- **接口统一**：相同功能的组件应实现统一接口
- **适配器模式**：使用适配器模式封装不同实现的组件
- **工厂模式**：使用工厂模式创建组件实例
- **依赖注入**：通过依赖注入实现组件替换

### 3.3 模块化要求

#### 3.3.1 模块划分原则

- **按功能划分**：每个模块负责一个独立的功能领域
- **按层次划分**：UI 层、业务逻辑层、数据层清晰分离
- **按领域划分**：笔记本、笔记、语音等业务领域独立模块

#### 3.3.2 模块目录结构

```
src/
├── modules/                    # 业务模块
│   ├── notebook/              # 笔记本模块
│   │   ├── components/        # 模块组件
│   │   ├── services/          # 模块服务
│   │   ├── store/             # 模块状态
│   │   ├── hooks/             # 模块 Hooks
│   │   ├── utils/             # 模块工具
│   │   └── index.js           # 模块入口
│   ├── note/                  # 笔记模块
│   ├── voice/                 # 语音模块
│   └── ai/                    # AI 模块
├── core/                      # 核心模块
│   ├── auth/                  # 认证核心
│   ├── api/                   # API 核心
│   └── storage/               # 存储核心
└── shared/                    # 共享模块
    ├── components/            # 共享组件
    ├── hooks/                 # 共享 Hooks
    └── utils/                 # 共享工具
```

#### 3.3.3 模块接口设计

- **模块入口**：每个模块通过 `index.js` 暴露公共接口
- **依赖管理**：模块间依赖通过依赖注入或导入语句明确声明
- **模块隔离**：模块内部实现细节不对外暴露
- **模块通信**：模块间通过明确的接口或事件通信

#### 3.3.4 服务层设计

- **服务抽象**：业务逻辑抽象为独立的服务类
- **服务接口**：定义统一的服务接口，便于替换实现
- **服务注册**：通过服务注册机制管理服务实例
- **服务依赖**：服务间依赖通过依赖注入管理

#### 3.3.5 数据层设计

- **数据模型**：定义清晰的数据模型和类型
- **数据访问**：通过 Repository 模式封装数据访问
- **数据转换**：使用 DTO 模式进行数据转换
- **数据验证**：在数据层进行数据验证

#### 3.3.6 配置管理

- **集中配置**：所有配置集中在 `config.json` 管理
- **环境配置**：支持多环境配置（development、test、production）
- **配置注入**：通过依赖注入将配置注入到模块
- **配置验证**：启动时验证配置完整性

### 3.4 扩展性设计

#### 3.4.1 编辑器扩展

- **编辑器接口**：定义统一的编辑器接口
  ```javascript
  interface IEditor {
    initialize(config: EditorConfig): void;
    getContent(): EditorContent;
    setContent(content: EditorContent): void;
    destroy(): void;
    onSave(callback: Function): void;
  }
  ```
- **编辑器工厂**：使用工厂模式创建不同类型编辑器
- **编辑器注册**：支持动态注册新编辑器类型
- **编辑器适配器**：为不同编辑器实现提供适配器

#### 3.4.2 认证扩展

- **认证策略接口**：定义统一的认证策略接口
  ```javascript
  interface IAuthStrategy {
    authenticate(credentials: Credentials): Promise<AuthResult>;
    refreshToken(token: string): Promise<string>;
    logout(): Promise<void>;
  }
  ```
- **认证策略注册**：支持注册多种认证策略（IDaaS、Welink）
- **认证策略选择**：根据配置动态选择认证策略

#### 3.4.3 存储扩展

- **存储接口**：定义统一的存储接口
  ```javascript
  interface IStorage {
    upload(file: File): Promise<string>;
    download(url: string): Promise<Blob>;
    delete(url: string): Promise<void>;
  }
  ```
- **存储实现**：支持本地存储、OBS 存储等多种实现
- **存储切换**：通过配置切换存储实现

#### 3.4.4 AI 服务扩展

- **AI 服务接口**：定义统一的 AI 服务接口
- **AI 服务适配器**：为不同 AI 服务提供适配器
- **AI 服务配置**：支持配置不同的 AI 服务端点

### 3.5 替换性设计

#### 3.5.1 组件替换

- **接口契约**：替换组件必须实现相同的接口契约
- **行为一致性**：替换组件应保持相同的行为和语义
- **测试覆盖**：替换组件需要通过相同的测试用例
- **文档更新**：替换后更新相关文档

#### 3.5.2 模块替换

- **模块接口**：替换模块必须暴露相同的公共接口
- **依赖兼容**：替换模块的依赖应与原模块兼容
- **配置兼容**：替换模块应支持相同的配置格式
- **迁移指南**：提供模块替换的迁移指南

#### 3.5.3 服务替换

- **服务接口**：替换服务必须实现相同的服务接口
- **API 兼容**：替换服务的 API 应与原服务兼容
- **数据格式**：替换服务应返回相同的数据格式
- **错误处理**：替换服务应使用相同的错误处理机制

### 3.6 代码组织规范

#### 3.6.1 文件组织

- **一个文件一个组件**：每个组件独立一个文件
- **一个文件一个模块**：每个模块独立一个目录
- **相关文件就近**：相关的组件、样式、测试文件放在同一目录
- **索引文件**：每个目录提供 index.js 导出公共接口

#### 3.6.2 代码分层

```
组件层（Components）
    ↓ 调用
业务逻辑层（Services/Hooks）
    ↓ 调用
数据访问层（API/Repository）
    ↓ 调用
数据层（Models/Store）
```

#### 3.6.3 依赖方向

- 上层可以依赖下层
- 下层不能依赖上层
- 同层模块间尽量减少依赖
- 跨层依赖通过事件或接口解耦

### 3.7 Git 提交规范

- feat: 新功能
- fix: 修复 bug
- docs: 文档更新
- style: 代码格式调整
- refactor: 重构
- test: 测试相关
- chore: 构建/工具相关
- component: 组件相关修改
- module: 模块相关修改

### 3.8 代码审查要点

- **组件化检查**：
  - 组件是否职责单一
  - 组件是否可复用
  - 组件接口是否清晰
  - 组件是否易于替换

### 3.9 架构约束与强制要求

#### 3.9.1 严禁事项

- ❌ **严禁在一个文件中实现多个不相关功能**
  - 每个组件必须独立文件
  - 每个服务必须独立文件
  - 每个工具函数库必须独立文件

- ❌ **严禁组件间紧耦合**
  - 禁止直接引用其他组件的内部状态
  - 禁止直接调用其他组件的内部方法
  - 必须通过 Props、事件或状态管理通信

- ❌ **严禁在组件中直接调用 API**
  - 必须通过 Service 层调用 API
  - 组件只负责 UI 渲染和用户交互
  - 业务逻辑必须在 Service 或 Hook 中

- ❌ **严禁硬编码配置和常量**
  - 配置必须放在 config.json
  - 常量必须放在 constants 文件
  - 魔法数字必须定义为常量

- ❌ **严禁循环依赖**
  - 模块 A 依赖 B，B 不能依赖 A
  - 使用事件或接口解耦循环依赖
  - 使用依赖注入避免循环依赖

#### 3.9.2 必须遵守

- ✅ **必须定义组件接口**
  - 使用 TypeScript 或 PropTypes
  - 明确 Props 类型和默认值
  - 提供清晰的文档注释

- ✅ **必须实现模块入口**
  - 每个模块必须有 index.js
  - 只暴露公共接口
  - 隐藏内部实现细节

- ✅ **必须编写单元测试**
  - 核心组件必须有测试
  - 关键业务逻辑必须有测试
  - 测试覆盖率 > 80%

- ✅ **必须进行代码审查**
  - 所有代码必须经过审查
  - 审查清单必须包含组件化、模块化检查
  - 不符合规范的代码不能合并

- ✅ **必须更新文档**
  - 新增组件必须更新组件文档
  - 新增模块必须更新模块文档
  - 接口变更必须更新 API 文档

#### 3.9.3 架构演进支持

- **版本化接口**：
  - 接口变更时保留旧版本
  - 提供迁移工具和文档
  - 支持渐进式升级

- **功能开关**：

- **配置驱动**：
  - 功能行为通过配置控制
  - 支持运行时配置更新
  - 减少代码修改

#### 3.9.4 质量保障

- **静态分析**：
  - 使用 ESLint 进行代码检查
  - 使用 TypeScript 进行类型检查
  - 使用 SonarQube 进行质量分析

- **自动化测试**：
  - 单元测试：Jest + React Testing Library
  - 集成测试：测试模块间交互

## 五、注意事项

1. **认证安全**：敏感信息（如 client secret）不应存储在前端配置文件中
2. **请求三元组**：每次请求必须携带 cloud_doc_token、cloud_doc_userid、cloud_doc_appid
3. **实时保存**：编辑器需要实现自动保存功能
4. **错误处理**：所有 API 调用需要完善的错误处理
5. **性能优化**：注意代码分割和懒加载
6. **响应式设计**：适配不同屏幕尺寸
7. **无障碍设计**：支持键盘导航和屏幕阅读器
8. **测试覆盖**：关键功能需要编写测试用例
9. **Electron 安全**：
   - 禁用 nodeIntegration，使用 contextBridge
   - 验证所有 IPC 通信
   - 限制 webview 和外部链接
   - 启用 contextIsolation
10. **Electron 性能**：
    - 优化主进程和渲染进程通信
    - 避免阻塞主进程
    - 合理使用 BrowserWindow 的 webPreferences
11. **跨平台兼容**：
    - 测试不同操作系统的表现
    - 处理平台特定的文件路径
    - 适配不同平台的快捷键
    - 处理不同平台的窗口行为
